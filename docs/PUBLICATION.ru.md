# Выпуск приложения

[English](PUBLICATION.md#releasing-the-application)

Инструкция предназначена для подготовки переносимого Windows EXE.
Запуск для разработки описан в [разделе «Разработка»](../README.ru.md#разработка).

## Доработки выпуска для OrientMark QR

Переносимый выпуск объединяет приложение и необходимые файлы в один EXE.
Пользователь запускает его без отдельной установки среды разработки.

| Компонент | Расположение | Роль |
|---|---|---|
| Подготовка выпуска | [build.ps1](../build.ps1) | Собирает приложение, добавляет распространяемые runtime-библиотеки и сведения о лицензиях, упаковывает один EXE. Поддерживает подпись обоих исполняемых файлов и выпуск без подписи с суффиксом `-unsigned`. |
| Переносимый запускатель | [tool/portable/launcher.cpp](../tool/portable/launcher.cpp) | Распаковывает встроенный архив в отдельную временную папку, запускает приложение и ждёт его завершения. При закрытии удаляет только созданную им папку. |

Переносимый запускатель используется только при упаковке в один EXE.
Обычный запуск для разработки не требует упаковки и сертификата подписи.

## Требования

Для сборки установите инструменты из [раздела «Разработка»](../README.ru.md#разработка).
Редактор кода можно выбрать любой; необходимые компоненты Visual Studio
должны быть установлены независимо от редактора.
Для подписанного выпуска дополнительно нужны SignTool из Windows SDK,
сертификат подписи кода с закрытым ключом в формате PFX и пароль к нему.

Все команды выполняются из корня проекта.

## Подписанный выпуск

Официальный релиз подписывается сертификатом издателя.

1. Укажите версию `x.y.z+build` в `pubspec.yaml`.
2. Скопируйте [.env.example](../.env.example) в `.env` и заполните параметры:
   - `APP_DEVELOPER` — имя разработчика.
   - `APP_ORGANIZATION` — организация.
   - `SIGNING_PFX_PATH` — путь к PFX.
   - `SIGNING_PFX_PASSWORD` — пароль.
   - `SIGNING_TIMESTAMP_URL` — необязательный сервер временных меток RFC 3161.
3. Выполните:

```powershell
.\build.ps1
```

Результат: `../OrientMark_relise/OrientMark-QR-<версия>.exe`.

```mermaid
flowchart LR
    Source["Исходный код"] --> Build["Release-сборка"]
    Build --> AppSignature["Подпись приложения"]
    AppSignature --> Package["Упаковка в переносимый EXE"]
    Package --> LauncherSignature["Подпись запускателя"]
    LauncherSignature -->|Вручную| Release["Публикация GitHub Release"]
```

Скрипт собирает приложение, добавляет runtime-библиотеки, подписывает внутренний
EXE и переносимый запускатель. Версия используется в имени файла, свойствах EXE
и интерфейсе.

Перед публикацией проверьте запуск приложения из итогового EXE.
Затем создайте релиз в [репозитории](https://github.com/orient-mark/qr-generator/releases)
и приложите файл. Сборочный скрипт не публикует релиз автоматически.

## Переносимый EXE без подписи

```powershell
.\build.ps1 -SkipSigning
```

Результат: `../OrientMark_relise/OrientMark-QR-<версия>-unsigned.exe`.

Для этого режима не нужны сертификат, пароль, файл `.env` и SignTool.
Это отдельный артефакт для сборки и проверки без ключа официального издателя.

Если `.env` существует, реквизиты разработчика и организации используются
и при сборке без подписи. Они отображаются в приложении, свойствах EXE
и сведениях об авторе PDF. При сборке без `.env` эти поля остаются пустыми.
